# kitdemo stack

The 3-entity proof app for K1 (food, meal, goal). One W2 app stack, `onelyf-kitdemo`, served at
`:8560/kitdemo` (citadel `docs/refactor/w2-confederation-plan.md`).

- `schema.json`: the kit schema. Change it, then run `npm run gen:sql` to regenerate the migration.
- `migrations/0001_kitdemo_init.sql`: generated by `schemaToSql`. Do not edit it by hand.

## Applying (Jeff, on Ravenry)
1. Stand up the stack from the W2 template. It needs `templates/db/auth-helpers.sql` mounted, so
   `auth.uid()` reads the platform token.
2. Apply `migrations/0001_kitdemo_init.sql` to the stack's database.
3. Expose only this schema: `PGRST_DB_SCHEMAS=kitdemo`, and also
   `alter role authenticator set pgrst.db_schemas = 'kitdemo'`. The role setting wins over the env if
   the two disagree.
4. Client: `stackBackend({ url: '<stack url>', key: '<publishable key>', schema: 'kitdemo', accessToken })`.

The owner-scoping tests in `engine/src/store/sql.test.ts` run this same migration against a local
Postgres with two users. Their `auth.uid()` has the same body as citadel
`infra/stacks/templates/db/auth-helpers.sql`: it reads `sub` from `request.jwt.claims` (what PostgREST v14
sets) and still honors the legacy `request.jwt.claim.sub`.

`stackBackend` refuses a service-role or `sb_secret_` key: pass only the publishable key.
